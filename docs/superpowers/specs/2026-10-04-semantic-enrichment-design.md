# Semantic Enrichment — Design

Status: Draft for review
Date: 2026-10-04
Implements: `DESIGN.md` §9.1 (enrichment), §6.5 (provenance), roadmap Notebook 1 step 4.

## 1. Goal

Make sparse menu items discoverable by meaning ("sweet", "light", "goes with
curry") without ever presenting inferred information as a menu fact.

The current dev menu has 744 items in 56 categories. Most items and all
categories lack descriptions, and some text is placeholder data ("Test cat",
"Test dummy description for testing"). Item embedding text is often just a
name and a category, for example `Plain Naan\nTest cat`.

Enrichment adds two kinds of inferred data:

1. **Inferred descriptions** for items with a missing or placeholder
   description, generated by a Gemini free-tier model.
2. **Semantic tags and scales** for every item, scored by Strands Decider 2B
   running locally.

Both feed retrieval (embedding text) and later ranking. Neither is used for
allergen, dietary, price or availability decisions.

## 2. Evidence from the spike

A throwaway spike ran Strands Decider 2B on an M1 with 8 GB of RAM (`mps`
device) against six hand-labeled dishes with descriptions:

- Yes/no tags: 26/26 correct at a 0.5 cut-off, 21/26 at 0.8 (5 abstained, 0 wrong).
- Scales (most likely level): 5/5 correct, but confidence only 0.31–0.44.
- About 5–7 s per dish for 13 questions in one call. The full menu takes about 75 minutes uncached.
- Probabilities are compressed: a clear yes is about 0.85–0.90 and a clear no about 0.15–0.20.
- `shareable` and `comfort_food` scored high for almost every dish.

Accuracy without descriptions has not yet been measured (see §11).

## 3. Pipeline position

```text
normalize -> validate -> generate missing descriptions -> score tags -> apply -> embed
             (blocking)   menu_descriptions.py            menu_enrichment.py
```

Enrichment runs only on a menu whose `ValidationReport` has no errors.
`apply_enrichment` returns a new `Menu`; the domain model stays immutable.

## 5. Module A — `menu_descriptions.py`

### 5.1 Selecting items

`needs_description(item) -> bool` is true when `item.description` is `None`
or matches a placeholder pattern. `PLACEHOLDER_PATTERNS` is a module-level,
case-insensitive regex tuple:

- `\btest\b.*\b(description|dummy)\b` and `\bdummy\b.*\bdescription\b`
- `\blorem ipsum\b`
- `^(n/?a|tbc|tbd|-|\.)$`

Category names are passed to the model as context, except names matching
`^test\b` (case-insensitive), which are dropped as placeholders. Option text
includes variation group names and their choice names, for example
`Spice level: Mild, Hot`.

### 5.2 Generator interface

```python
@dataclass(frozen=True)
class DescriptionRequest:
    item_id: str
    name: str
    category_names: tuple[str, ...]
    option_names: tuple[str, ...]      # "Group: Choice, Choice"

class DescriptionGenerator(Protocol):
    model_id: str
    def generate(self, requests: Sequence[DescriptionRequest]) -> Mapping[str, str | None]:
        """One model request. Return item_id -> description, or None when not recognizable."""
```

### 5.3 Gemini implementation

`GeminiDescriptionGenerator`:

- Uses the `google-genai` SDK, imported lazily so the module and its tests do
  not require it. A client can be injected for tests.
- Reads the API key from `GEMINI_API_KEY`. A missing key raises a clear error.
  The key is never written to code, notebooks or the cache.
- `model` defaults to `"gemini-2.5-flash"` and can be overridden (for example
  with a Gemini 3 Flash ID from AI Studio, which has a higher daily quota).
- Uses JSON structured output with a response schema: a list of
  `{item_id, status: "described" | "unknown", description}`. Temperature 0.
- Waits at least `60 / requests_per_minute` seconds between requests
  (default 10 RPM). On HTTP 429 or 5xx it retries with exponential backoff, up
  to 3 times, then raises `DescriptionGenerationError`. Other errors and
  invalid JSON raise `DescriptionGenerationError` immediately.

Prompt rules (versioned as `PROMPT_VERSION = "v1"`):

- Describe only the general dish: style, taste, texture and typical role
  (side, main, drink, dessert), in at most 2 sentences and 200 characters.
- Do not mention allergens, dietary suitability (vegan, vegetarian, halal,
  gluten-free and so on), health claims, prices, portion sizes or availability.
- Phrase typical ingredients as typical ("usually made with…"), never as a fact
  about this restaurant.
- If the name is not a recognizable dish or drink (for example "Meal Deal 2",
  "House Special"), return `status: "unknown"`.

### 5.4 Deterministic guard

Every generated description passes `check_description(text) -> str | None`
before use. It returns a rejection reason when:

- the text is empty or longer than 200 characters, or
- it contains a term from `FORBIDDEN_TERMS`: allergen and dietary vocabulary
  such as `vegan`, `vegetarian`, `halal`, `kosher`, `gluten`, `nut(s)`,
  `peanut(s)`, `dairy-free`, `lactose`, `allergen(s)`, `allergy`, `allergies`,
  `healthy`, `low-calorie`, matched case-insensitively on whole words (so
  "coconut" and "doughnut" are not rejected).

Responses for item IDs that were not requested are ignored. Requested IDs
missing from the response, and `described` rows with empty text, are recorded
as `unknown`.

### 5.5 Result and orchestration

```python
@dataclass(frozen=True)
class DescriptionResult:
    item_id: str
    status: str              # "described" | "unknown" | "rejected"
    text: str | None         # set only when status == "described"
    reason: str | None       # rejection reason
    model_id: str
    prompt_version: str
    input_hash: str          # sha256 of the DescriptionRequest content
```

`generate_descriptions(menu, generator, cache, *, cache_path=None, batch_size=25) -> tuple[DescriptionResult, ...]`:

- Processes only items that need a description and are not already cached
  under the same input hash, model and prompt version.
- Sends `batch_size` items per generator call, so the full menu takes about 30
  requests and stays well inside free-tier daily quotas.
- Saves the cache after every batch when `cache_path` is given, so a quota
  error or crash keeps completed batches and a rerun resumes.
- Returns results for every item needing a description, in menu order.

## 6. Module B — `menu_enrichment.py`

### 6.1 Vocabulary

Closed and versioned (`VOCABULARY_VERSION = "v1"`):

- Yes/no tags: `sweet`, `spicy`, `savory`, `light`, `filling`, `refreshing`,
  `rich`, `shareable`, `breakfast`, `dessert`, `comfort_food`.
- Scales: `spice_level` (`not spicy, mild, medium, hot`) and `heaviness`
  (`light, moderate, heavy`).

A unit test asserts that no vocabulary name, question or level contains a
`FORBIDDEN_TERMS` entry.

### 6.2 Decider input

`describe_item(item, menu, inferred_description=None) -> ItemText` returns the
text the decider reads and an `input_level`:

| `input_level` | Text contains |
|---|---|
| `source_description` | name, categories, source description, options |
| `inferred_description` | name, categories, `Inferred description: …`, options |
| `name_category` | name, real categories, options |
| `name_only` | name, options |

Empty fields and placeholder categories are omitted. An inferred description
is never used when the item has a real source description. The text is built
from fields, never from `embedding_text`, so re-enrichment cannot feed tags
back in.

### 6.3 Scorer interface

```python
@dataclass(frozen=True)
class ScaleScore:
    value: float                      # expected level, 0 (lowest) .. 1 (highest)
    probabilities: Mapping[str, float]
    confidence: float

@dataclass(frozen=True)
class ItemScores:
    tags: Mapping[str, float]
    scales: Mapping[str, ScaleScore]

class SemanticScorer(Protocol):
    model_id: str
    def score(self, text: str) -> ItemScores: ...
```

`StrandsDeciderScorer` implements it with `strands_decider.infer.load_engine`
(the package's real API; it has no `DeciderClient`), choosing `cuda`, then
`mps`, then `cpu`. All 13 questions go in one `engine.ask(state, questions)`
call per item, using `NoulQuestion` and `ScoreQuestion` from
`strands_decider.schema`. A score answer's expected level index is divided by
`levels - 1` to give `value`; its index-keyed probabilities are mapped to level
names through its legend. `strands_decider` and `torch` are imported lazily,
and an engine can be injected for tests.

Scores missing a vocabulary entry, or values outside 0–1, raise `ValueError`.

### 6.4 Result and orchestration

```python
@dataclass(frozen=True)
class TagResult:
    item_id: str
    input_level: str
    scores: ItemScores
    model_id: str
    vocabulary_version: str
    input_hash: str
```

`score_menu(menu, descriptions, scorer, cache, *, cache_path=None, save_every=25, progress=None) -> tuple[TagResult, ...]`:

- Skips items already cached under the same input hash, model and vocabulary
  version.
- Saves the cache every 25 newly scored items and again when the run ends,
  including when it is interrupted (crash or Ctrl-C).
- Calls `progress(done, total)` every 25 items and at the end.

## 7. Applying enrichment

`apply_enrichment(menu, descriptions, tags, *, threshold=0.7, excluded_tags=("shareable", "comfort_food")) -> Menu`:

- Raises `ValueError` if any item already has semantic attributes or an
  inferred description, if `threshold` is outside (0, 1], or if an excluded
  tag is not in the vocabulary. It is applied to a freshly normalized menu only.
- Sets `inferred_description` to
  `AttributedValue(text, "inferred", None, "<model> prompt <version>")` for
  `described` results, and only for items that still need a description.
- Sets `semantic_attributes` to one
  `AttributedValue(tag, "inferred", probability, "<model> vocab <version>")`
  for each tag with probability ≥ `threshold` that is not excluded, sorted by
  tag name.
- Scales do not become attributes. Their scores stay in the `TagResult` for
  ranking.
- Appends `Inferred description: …` and `Semantic attributes: a, b, c` lines to
  `embedding_text`.

The result must still pass `validate_menu` with no new errors.

## 8. Cache — `enrichment_cache.py`

Both enrichment modules use the cache, so it lives in its own small module
with `content_hash(text) -> str` (sha256).

One JSON file per menu: `enrichment/<menu_id>.json`, committed to git as a
reproducible record of model outputs.

```json
{
  "menu_id": "...",
  "descriptions": {"<item_id>": {"status": "...", "text": "...", "reason": null, "model_id": "...", "prompt_version": "v1", "input_hash": "..."}},
  "tags": {"<item_id>": {"input_level": "...", "scores": {"tags": {}, "scales": {}}, "model_id": "...", "vocabulary_version": "v1", "input_hash": "..."}}
}
```

- `EnrichmentCache.load(path, menu_id)` returns an empty cache when the file
  does not exist and raises `ValueError` when the file belongs to another menu.
- `EnrichmentCache.save(path)` creates parent directories and writes to a
  temporary file followed by an atomic rename, so an interrupted save cannot
  corrupt the cache.

## 10. Testing

Unit tests use `unittest`, fake generators, fake clients and fake scorers
only. No network, no model, no third-party imports:

- `needs_description` and placeholder detection.
- `check_description`: forbidden terms (including "Gluten-Free", "NUTS",
  "Nut"), whole-word matching ("coconut", "doughnut" accepted), length, empty
  text.
- Description orchestration: only items needing text are sent, batching, cache
  hits, re-processing on changed item text or model, completed batches kept
  when the generator fails.
- Gemini generator through an injected fake client: parsing, unrequested and
  blank rows, invalid JSON, retry on 429/5xx with backoff, giving up after
  retries, no retry on 4xx, request spacing, missing API key.
- `describe_item` input levels, placeholder-category removal, inferred text
  never replacing a source description.
- Vocabulary contains no forbidden terms.
- Tag scoring: cache hits, re-scoring on changed text, model or vocabulary
  version, saving on interruption, rejecting incomplete or out-of-range scores,
  progress callback.
- `apply_enrichment`: threshold, excluded tags, `inferred` origin and evidence,
  `description` unchanged, `embedding_text` lines, stale descriptions ignored,
  refusal on an already enriched menu, invalid arguments, `validate_menu`
  still passes.
- Strands adapter through an injected fake engine; question building tested
  only when `strands-decider` is installed.
- Cache round-trip, missing file, foreign menu, no leftover temporary files.

Model quality is checked manually in notebook 02 and by the comparison in §11.

## 13. Out of scope

- Human review workflow (`manually_confirmed` values). Raw scores stay in the
  cache for inspection.
- Inferred ingredients, allergens or dietary properties.
- Embeddings and retrieval (next roadmap step).
- Using scales or tag probabilities in ranking (designed with retrieval).

## 14. Risks

- **Gemini free tier:** Google may use free-tier prompts to improve its
  products. Menu names are public, so this is acceptable for the dev store.
  Quotas change without notice; caching and resumable batches limit the impact.
- **Wrong world knowledge:** an inferred description can be wrong for this
  restaurant's version of a dish. It is labeled inferred, never shown as a
  fact, and never used for safety decisions.
- **Run time:** about 75 minutes of decider scoring for the full menu on an M1.
  The cache makes later runs incremental.
